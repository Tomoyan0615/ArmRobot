# ArmRobot

XYZ座標で逆運動学を使う場合: `.\.venv\Scripts\python.exe ik_control.py`

従来の関節単位の操作: `.\.venv\Scripts\python.exe test.py`

`test.py` を終了してから `ik_control.py` を起動してください。COM10・115200bpsを共用するため同時起動はできません。

IK操作では、左スティック上下がX（前後）、左右がY（旋回方向）、右スティック上下がZ（上下）です。Aはハンド開閉・負荷検知、Bは全軸の停止・保持です。スティックを中央に戻すとアームをその位置で保持します。画面のXYZスライダーでも目標座標を指定できます。コントローラーの起動・再接続後はスティックを中央に戻してから操作してください。

制御点は**ハンド側リンクの回転軸中心**です。指先・つかむ位置のオフセットは含みません。原点は台座旋回軸上の肩軸高さ、X正方向はID1=180度の前方、Y正方向はID1の値が減る側（回転方向を反転済み）、Z正方向は上です。画面の現在座標はサーボ位置からの計算値で、座標センサーの実測値ではありません。

計算モデルは、上腕・前腕が各120mmで、平行リンクによってID2が上腕の絶対角、ID3が前腕の絶対角に1:1で対応するものです。全軸180度の姿勢で、上腕は水平から+45度、前腕は-45度です。ID2の増加で上腕が上がり、ID3の増加でハンドが下がるよう設定しています。この基準姿勢の制御点は(X,Y,Z)=(約169.7,0,0)mmになります。寸法・角度は `ik_control.py` の `GEOMETRY` で確認できます。肩軸と旋回軸のずれがある場合や指先の座標を指定したい場合は、追加のオフセット寸法をモデルに入れる必要があります。

`inverse_kinematics.py` が計算を担当し、絶対角度とID2+ID3の相対制限を満たす解だけを選びます。IKではXYZの移動に必要なID1～3を協調して動かします。従来の関節操作での「ID2操作でID3を自動追従させない」動作は `test.py` に残っています。

IKは目標へ小刻みに進め、送信直前にも既存の角度制限を確認します。目標が到達不可なら受け付けず、途中の座標が到達不可なら停止します。障害物を避ける経路探索は行いません。起動時には現在姿勢を読み取るだけで、移動しません。動作速度は `MOVE_SPEED_MM_S`（初期30mm/秒）で変更できます。実機精度は未検証です。

逆運動学の基本式の参考: [MathWorksの2リンクアームの導出](https://www.mathworks.com/help/symbolic/derive-and-apply-inverse-kinematics-to-robot-arm.html)。このアームでは前腕の絶対角を使うよう変換しています。

COM10・115200bpsで接続します。ID1～3はスライダーで操作し、ID4はボタンで閉じる位置1750／開く位置2300を切り替えます。

ID1の操作範囲は90～270度（位置値1024～3072）です。スライダーとコントローラーの両方に適用し、サーボ本体の角度制限がさらに狭い場合は、その範囲も守ります。

ID2の操作範囲は125～210度（位置値1423～2389）です。これもスライダー・コントローラーの両方に適用します。

ID3の絶対範囲は135～225度（位置値1536～2560）です。ID2とID3は向かい合わせなので、角度の和も305～395度に制限します。ID3は「305度−ID2の現在角度 ～ 395度−ID2の現在角度」と絶対範囲の共通部分で動かせます。ID2が180度ならID3は135～215度になります。

ID2を操作してもID3は自動で動かしません。代わりに、ID3の位置に応じてID2の可動範囲を狭めます。たとえばID3が225度ならID2は125～170度までです。スライダーの両端にも、その時点の許可範囲を表示します。

両軸の現在位置を約0.05秒間隔で読み取り、移動命令の送信直前にも読み直して確認します。同時操作では、他方の現在位置から送信済みの目標位置までの移動中も角度の和が収まるように制限します。そのため、表示範囲が一時的に狭くなる場合があります。これはアプリの移動目標の制限で、サーボ本体の角度制限設定は書き換えません。

Xbox 360形式のコントローラーをUSB接続すると自動で認識します。画面をクリックしてアクティブにし、スティックを中央に戻してA・Bを離してから操作してください。

| 操作 | 動作 |
| --- | --- |
| 左スティック左右 | ID1の位置を変更 |
| 左スティック上下 | ID2の位置を変更（上で位置値が増える） |
| 右スティック上下 | ID3の位置を変更（上で位置値が増える） |
| Aボタン | ハンドの開閉を切り替え。閉じるときは負荷を監視 |
| Bボタン | 全軸の移動を止め、現在位置を保持。中央に戻してから操作再開 |

スティックは倒した量で移動速度が変わり、中央に戻すとその位置を保持します。接続が切れたときや画面が非アクティブになったときも、現在位置を読み取って保持する命令を送ります。トルクを解除する操作ではありません。通信そのものが途切れた場合は停止命令を届けられません。

位置変更の速さは `test.py` の `GAMEPAD_SPEED`、関節操作のID1反転は `GAMEPAD_ID1_DIRECTION`、IK操作のID1反転は `ik_control.py` の `GEOMETRY.yaw_direction` で設定します。その他のスティックの向きと中央の遊びは `xbox_controller.py` の `AXES` と `DEADZONE` で変更できます。コントローラー未接続でもマウスで操作できます。

ID4を閉じるときは少しずつ動かし、現在位置と負荷を約0.05秒間隔で読み取ります。負荷がしきい値を2回連続で超えると、その位置を目標として保持します。次のクリックで開きます。閉じ位置まで到着した場合や15秒経過した場合も閉じる動作を終了します。

画面の「負荷」はサーボの出力の目安（PWM比率）で、実測トルクではありません。機構の摩擦や加速でも増えるため、物体をつかんだことを確実に判定するものではありません。

`test.py` 冒頭の `GRIPPER_LOAD_THRESHOLD = 200` が検知しきい値です。0.1%単位なので200は20%です。何も挟まずに閉じたときの値を画面で確認し、接触時に反応するよう実機で調整してください。ID4の速度は `GRIPPER_SPEED`、1回に進める量は `GRIPPER_CLOSE_STEP` で変更できます。

組み立て用の中央位置合わせ: `.\.venv\Scripts\python.exe center_servos.py`

同時に起動するとCOMポートが競合するため、片方を終了してから実行してください。いずれも終了時にトルク保持を自動解除しません。

実機を使わない負荷検知のテスト: `.\.venv\Scripts\python.exe -m unittest discover -s tests -v`
